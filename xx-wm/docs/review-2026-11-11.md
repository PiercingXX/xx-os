# XX-WM review — fix list (2026-11-11)

Whole-shell review of `main` at `d217514` (58k lines under `launcher/`, plus helper,
install scripts and tests). Six read-only reviewers covered: core/home/drawer,
lock/shade/notifications, windowing/display/standby/wireless debugging, telephony,
settings/backup/updates, root helper/install/tests. Findings were then checked against
`origin/tier2` (7 commits ahead of `main`) and against a live FLX1.

**How to use this file.** Work top to bottom. Each item has: where, what is wrong, what
to do, and the test that must fail before the fix. Paths are relative to
`xx-wm/launcher/src/` unless they start with another directory. Line numbers are for
`main` at `d217514`; on `tier2` they shift.

**Labels.** `[traced]` = the code path was read end to end. `[reproduced]` = a reviewer
ran it. `[device]` = logic traced, effect needs a phone. `[tier2: fixed]` = already
fixed on `origin/tier2`, verify and skip. `[tier2: open]` = checked, still present there.
Unlabelled items were not checked against tier2.

**Base branch.** Do this work on top of `tier2` once it is merged, or rebase onto it:
it rewrites the lock, PIN storage, modem monitor and helper, which most P0/P1 items touch.

**Ground rules** (from `todo.md`, still in force): `design.md` is the contract; nothing
blocks the GTK main loop; `sh scripts/check.sh` green before every commit; a change is
done when it is seen on the rig or a device, not when pytest passes; minimal UI (no
empty-state lines, no decorative glyphs, no popups for direct manipulation); no AI
attribution in commits or files.

## P0 — security and "the phone does the wrong dangerous thing"

### P0.1 Root helper: nft command injection through the cgroup path `[reproduced]` `[tier2: open]`
- Where: `launcher/helper/xx_wm_helper.py:421-443` (`validate_app_cgroup`), `:456-461`
  (`cgroup_nft_match`), `:490-496` (`apply_blocked`), `:474` (stderr returned to caller).
- Wrong: the path is wrapped as `'"%s"' % rel` and handed to `nft` as one argv element.
  `nft` re-joins and re-parses argv, and the validator allows `"`, `;`, spaces and paths
  that do not exist. `SetAppNetwork` is polkit `allow_active=yes`, so any process in the
  session can run arbitrary nft statements as root with no prompt (flush the ruleset,
  add NAT). With `include "/etc/shadow"` the parse errors come back in the D-Bus error,
  so it is also a root file read. A payload that succeeds is saved to `state.json` and
  replayed at every boot.
- Do: validate every path component after the prefix against `^[A-Za-z0-9_.:@\\-]+$`;
  require `os.path.isdir(path)`; re-validate persisted paths in `apply_saved`; never
  return raw nft stderr to the caller. Better: build one JSON ruleset and feed it with
  `nft -j -f -` so a path is never grammar (this also fixes P1.6).
- Test: run `HelperCore` against real `nft` inside `unshare -rn` with hostile paths
  (`"`, `;`, `include`, `{`, newline, non-existent); skip when `unshare` is unavailable.

### P0.2 App standby freezes the app in use `[reproduced]` `[tier2: open]`
- Where: `app_standby.py:674-686` (`track`), `:819-824` (`note_activated`), callers
  `window.py:1508`, `app_index.py:213`, `app_standby.py:1133,1164`;
  `app_switcher.py:463,471`; `window.py:1940`.
- Wrong: `track()` is keyed by the desktop id (`org.gnome.Calculator.desktop`) and
  `note_activated()` by the Wayland app_id (`org.gnome.Calculator`). Two records exist;
  the one holding the pid never has `last_active` refreshed. `app_standby_minutes`
  defaults to 10, so every shell-launched app is frozen 10 minutes after launch while
  on screen. The switcher and the neighbour gesture call `manager.activate/close`
  directly, so a frozen app raised from recents stays hung and ✕ cannot close it
  (`activate_with_thaw` is dead code).
- Do: key `_apps` by `normalize_app_id()` everywhere, with an alias map for
  StartupWMClass mismatches; route switcher activate/close and the neighbour gesture
  through the controller so it thaws first.
- Test: track `X.desktop`, activate toplevel `X`, sweep at +11 min → nothing frozen.
- Related, same module:
  - `:946-994` falls back to `SIGSTOP` on a raw pid with no start-time check when the
    scope is gone; `rec.pids` is never pruned. Pid reuse can stop phoc, pipewire or the
    keyboard `[device]`. The FLX1 log shows this fallback firing
    (`FreezeUnit failed, stopping pid …`). Record `/proc/<pid>/stat` start time at
    `track()`, verify before every STOP/CONT, treat "unit not loaded" as "app exited".
  - `:411-439, 1214-1302`: audio/MPRIS exemptions miss child processes and id
    mismatches; a failed `pw-dump` reads as "nobody is playing"; a frozen player is
    never thawed by a headset key; Email/Chat/SoftPhone are not exempt and stop
    receiving 120 s after blank.
  - `:828-878, 1323-1373`: units frozen via D-Bus activation stay frozen after a shell
    crash or deploy (`SIGUSR1` skips `do_shutdown`). Keep a frozen-units ledger in
    `$XDG_RUNTIME_DIR` and thaw it at start.
  - `:1170-1189`: auto battery saver does not re-arm after a charge while still low.
  - `:694-808`: `network_denied_apps` silently does nothing for Flatpak and
    D-Bus-activated apps; surface "not enforced".

### P0.3 Wireless debugging (xxdb) `[traced]`
Off by default (`xxdb_enabled: false`), so exposure needs the user to switch it on. Once
on, these hold:
- **Pairing is MITM-able.** `tools/xxdb:290-298` sends `'code': args.code` in plaintext
  over a `CERT_NONE` connection (`tools/xxdb:158-160`); the docstring says the code is
  never sent. The HMAC is keyed only by a 6-digit code. The client stores
  `response['phone_fp']` instead of the fingerprint it observed. An attacker on the LAN
  (ARP spoof or a fake `_xxdb._tcp` advert) pairs itself with the real phone in one try.
  Do: never transmit the code; show a fingerprint prefix with the code and have the
  client refuse a mismatch (or a commit-then-reveal SAS / PAKE); pin the observed cert.
- **Unauthenticated connections drive GTK from a worker thread.**
  `xxdb_daemon.py:381-385, 441-445` → `xxdb_controller.py:221-248` → `main.py:771-778`
  call `shade.add_notification` without the `post()` hop. Any LAN host can do it.
  `on_connect` sits outside the `try/finally`, so one exception leaks the socket and
  pins `active_clients`, and idle auto-off never fires.
- **Pre-auth DoS.** `xxdb.py:26, 194-206`: a 768 MiB line is accepted before any auth
  check and re-scanned from offset 0 on each feed. `xxdb_daemon.py:354-371`: the TLS
  handshake runs inline in the accept loop with no timeout. No connection cap.
  Do: 64 KiB frame cap until authorised; handshake in the per-connection thread with a
  10 s timeout; cap connections and unauthenticated lifetime.
- **Off does not mean off.** `xxdb_daemon.py:337-352, 395-412`,
  `xxdb_controller.py:93-151`: `stop()` closes listeners only; live sessions and PTYs
  keep running; a disable during start is undone when the daemon finishes starting.
- **A paired host is root, permanently, including while locked.** `shell` runs as the
  session user (passwordless sudo on the test devices). The `--system` confirmation
  token is not bound to the path it was shown for (`xxdb_daemon.py:713-731`). Trust
  never expires; `forget_host` does not drop live sessions; nothing checks lock state.
  Do: bind tokens to the resolved path; refuse everything but `hello` while locked
  unless opted in; add trust expiry; say "paired host = full control" in the UI and in
  `docs/config.md`.
- **Stream state is keyed by a client-chosen request id across all connections**
  (`xxdb_daemon.py:242-244, 572, 606-627`), and the client hardcodes `1`: a second
  `xxdb shell` takes over the first one's PTY. Keep the maps on the session object.
- **PTY lifecycle** `[reproduced]` (`xxdb_daemon.py:558-624`): no `waitpid`, so a
  finished shell leaves a 20 Hz spin and `pty-done` is never sent; a dropped connection
  leaves the remote shell running.
- **`xxdb deploy` cannot restart the shell and damages ownership**
  (`xxdb_daemon.py:147-162, 817-837`): the restarter skips its own pid, but the daemon
  is the shell; `sudo rsync -a` makes `/usr/share/xx-wm` user-owned.
- Recommended shape: run xxdb as its own user unit, so off = stop the unit and a crash
  or OOM in it cannot take the shell down.

### P0.4 Lock: Smart Lock, restore and PIN rules `[traced]` `[tier2: open]`
- `smart_lock.py:194-219`: Bluetooth trust is "a device with that address has
  `Connected=true`". No `Paired`/`Bonded` check. A spoofed address unlocks within the
  4 h window `[device]`. Require `Paired and Bonded and ServicesResolved` plus a
  connected profile; drop entries whose device is no longer bonded.
- `smart_lock.py:222-245`: Wi-Fi trust is the NetworkManager profile **name**. No BSSID,
  no security check; open networks are offered. An AP with the same SSID unlocks.
  Store `{ssid, bssid}` from the connected AP; refuse open/OWE networks.
- `settings_smart_lock.py:167-206`: trust is added without asking for the PIN.
- `backup.py:123-124, 433-435, 458-459` + `settings_page.py:2600-2626`: Restore asks for
  no PIN, restores the Smart Lock trust lists, and restores `auto_lock_timeout` with no
  upper bound. A file named `xx-wm-backup-99991231_235959.json` dropped into
  `~/Documents` (Nearby Share, Syncthing) sorts first in the picker. Require the PIN for
  Restore and for adding trust; drop `smart_lock_*` from the restore allowlist; clamp
  the timeout.
- `settings_lock.py:42-52`: Change PIN accepts any 1–64 character string. A 1-digit PIN
  is accepted; a PIN with a non-digit cannot be typed on the lock keypad and locks the
  owner out. Share one `valid_pin()` (digits, ≥ 6) with `first_boot.py`. Add a Remove
  PIN row that verifies the PIN first.
- `lock_screen.py:1072-1116`: `lock_screen_medical_id = false` hides the Medical info
  button but emergency-contact names and numbers still show and dial without a PIN.
- `[tier2: fixed]` Lock not restored after a shell crash/restart/boot
  (`main.py:118-126`, `window.py:1626-1660`). tier2 boots and crash-restarts locked
  behind phoc's `-S` shield and moves the PIN to the root helper. Verify on a device
  (see `devices/furiphone-flx1/tier2-device-facts.md`), then check that a corrupt
  `config.json` can no longer remove the PIN (P1.1).

### P0.6 Updates and installers run unverified code as root `[traced]`
- `xx_apps_update.py:33-39, 82-103, 320-352, 464-480`: "Update now" builds whatever
  GitHub `main` HEAD is and runs `meson install` via `sudo -n`/`pkexec`. No signature,
  no tag. One bad push or a compromised account is root on every phone. Update only
  from signed tags or a signed manifest (minisign or ssh-sig; public key shipped in the
  package; tarball sha256 inside the manifest); refuse a commit that is not a
  descendant of the installed one.
- `scripts/apps.sh:234`: `curl -s https://repo.waydro.id | $SUDO bash`.
  `scripts/apps.sh:155-160`: Tailscale tarball piped into `tar` with no checksum.
  `scripts/bootstrap-dots.sh:35`: unpinned clone whose `update-system.sh` self-updates.
  `scripts/install.sh:325`: font zip pinned by version, no checksum.
- `scripts/apps.sh:252`: installs `openssh-server` on apt; Debian enables and starts it
  with password auth. Run `systemctl disable --now ssh` after install or do not install
  it until the user turns SSH on in Settings.

### P0.7 "Update now" kills the package manager mid-transaction `[traced]` `[tier2: open]`
- `launcher/helper/xx_wm_helper.py:306-309` (`timeout=30`), used by `upgrade_system:672`
  and `remove_package:695`; `helper_client.py:24` (`_CALL_TIMEOUT_MS = 25_000`).
- Wrong: `subprocess.run` SIGKILLs `apk upgrade` / `pacman -Rns` at 30 s. The client
  gives up at 25 s, and that window includes typing the polkit password. Everything
  runs synchronously on the helper's main loop.
- Do: long jobs via `Gio.Subprocess` or a worker with no kill timeout; reply with a job
  id and emit `JobFinished(id, rc, tail)`; suspend idle-exit while a job runs;
  per-method client timeouts.
- Also `xx_wm_helper.py:1340-1344`: the interactive polkit check times out after 10 s
  while the password dialog is still open.

### P0.8 The Firewall switch filters nothing but says "Blocking all incoming" `[traced]` `[tier2: open]`
- `launcher/helper/xx_wm_helper.py:921-938, 987-1008`; `settings_firewall.py:124-134`.
- The managed chain is `policy accept` with only `accept` rules. Either render a real
  policy (`policy drop; ct state established,related accept; iif lo accept;` ICMP,
  DHCP, then presets, and make enabling `auth_admin_keep` since it can cut SSH), or
  rename the row to what it does. Never show "Blocking" unless a drop policy is
  verified.
- `settings_firewall.py:272` calls `probe_features(xxdb_enabled=xxdb)`; the parameter
  is `xxdb` (`:197`). The `TypeError` is swallowed, so every re-apply fails with
  "feature probe failed" `[reproduced]`. `tests/test_firewall_rows.py:452` stubs the
  function with the wrong signature, which hides it.
- `xx_wm_helper.py:1010-1054`: state is read by substring (`'dport 22'` matches 22000).
  Parse `nft -j`.
- `xx_wm_helper.py:1104-1112`: the ufw "keep port 22" safeguard reads `SSH_CONNECTION`
  in a D-Bus-activated daemon, where it is never set.

### P1.6 Per-app network blocking fails open `[traced]`
- `launcher/helper/xx_wm_helper.py:478-513, 1246-1255`; `app_standby.py:114`.

## P3 — performance and battery

- Timers that never stop: home clock 1 Hz (`window.py:840`, builds a `Gio.Settings`
  each second when `clock_24h` is null), lock clock 1 Hz, media position 1 Hz while the

  (`settings_page.py:1051-1084, 1479-1494`), including `dpkg -S` once per installed app

## Suggestions and improvements

Architecture
- **Split `window.py` (2,900 lines).** Seams: `shell_theme.py` (theme resolve, CSS
  templates, re-theme fan-out); `layer_policy.py` (one state machine for layer and
  keyboard mode — today five flags coordinate it, which is where the Settings-back bug
  comes from); `home_gestures.py`; `toplevel_watch.py`; `config_watch.py`;
  `lock_controller.py` (single owner of lock state with real callbacks, replacing
  `main._wire_usage_lock`'s monkeypatch — today a lock from the power menu misses the
  usage tracker). Remove the ~75 pure delegator methods.
- **Split `settings_page.py` (2,630 lines)** into `settings_wifi.py`,
  `settings_bluetooth.py`, the update flow into `settings_updates.py`,
  `settings_backup.py`, `settings_developer.py`, `settings_gestures.py`. Stop storing
  section widgets on `win`.
- **One notification policy function.** Mute → Nope → Focus → DnD → sound → banner is
  inline in `main._on_notification`, and the three stages match apps three different
  ways. Make it a pure `decide(notification, state)`.
- **One `ShellConfig` per process** (three are constructed today) and one shared
  `ToplevelManager`.
- **Harden the helper unit**: ship a `Type=dbus` unit with `NoNewPrivileges`,
  `ProtectHome`, `PrivateTmp`, `RestrictNamespaces`, `SystemCallArchitectures=native`,
  `StateDirectory=xx-wm-helper`; split package operations into a second job runner so
  the main helper can take `ProtectSystem=strict`.
- **Real packages** (APKBUILD, PKGBUILD, debian/) instead of `sudo meson install` into
  `/usr`: uninstall, file ownership and signed updates come for free, and
  `xx-apps-update` becomes a thin wrapper over the package manager.

Settings a daily-driver phone still needs in the UI (the config keys exist, file-only)
- Screen timeout and auto-lock delay; lock-screen notifications mode.
- Ringtone/notification sound, vibration, DnD and Focus schedules.
- Date, time, timezone.
- Mobile data, roaming, preferred network type; hotspot; VPN.
- Brightness and auto-brightness under Display.
- A list of existing backups with delete.

UX, in keeping with text-first and minimal
- Lock: cap notification rows with "+N more"; hide shade/switcher/power menu when the
  lock engages; option to require unlock for Restart and Power off.
- Calls: proximity blanking in `DisplayManager`; a power-key double-press to end a call
  as the fallback when the proximity sensor sticks; show the end reason (busy, no
  service) for two seconds before closing.
- Drawer: clear search and return home after any launch; A–Z strip shows only letters
  that exist and hides during search.
- Smart Lock settings: per-entry status (connected, bonded) and a warning on open
  networks.
- Captions tile: show the source (playback, call, mic), so a session started by
  another client is not indistinguishable.

FLX1-specific work (details in `devices/furiphone-flx1/tier2-device-facts.md`)
- Automatic suspend must switch itself off when logind `CanSuspend` is not `yes`.
- The RTC wake alarm must be written in RTC time, not system time.
- Torch lives at `/sys/class/flashlight/mt-flash-led*`, not under `/sys/class/leds`.
- No `charge_control_end_threshold`: the charge-limit rows should not appear.
